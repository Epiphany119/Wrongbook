## 1. 背景与目标

学生需要快速把历史题目加入错题本。当前产品已支持拍照/相册和错题记录，但录入步骤、图片识题和首页信息层级还需要按“快、清楚、容易找到”进一步设计。

本次目标：

1. 从首页快速进入拍题或文字录题。
2. 用视觉模型识题减少重复打字；识别结果必须能由学生校对。
3. 让学生可以先保存题目，再补充非必填分类和订正信息。
4. 首页突出当前最重要的学习任务和录题动作，降低寻找入口的时间。
5. 复习评分可用文字记录；需要时可添加图片并通过 OCR 辅助提取文字。

## 2. 范围与边界

### 2.1 本稿范围

- 首页快捷录题入口和首页信息层级。
- 相机拍照和相册选择题目；若“扫描”指自动裁边或透视矫正，则需先确认后纳入。
- 图片识题整理题干、选项及图片可见的答案，生成可编辑草稿。
- 手动文字录题和图片识题失败后的备用流程。
- 复习结果、自评文字和图片附件的录入体验。
- 选择题点选后的即时判定和解析展示；缺少标准答案时由学生自评。
- 解析下方展示作者录入的题型/错因，并允许学生新增随笔、之后回看。
- 录入耗时、点击步骤和视觉模型响应的建议验收指标。

### 2.2 本稿不包含

- 家长端、教师端或多角色工作台。
- 多学科管理；当前只针对历史。
- 批量多题识别、复杂图片标注、AI 解题或自动生成答案。
- 自动评判材料分析题、论述题或手写答案的正确性。
- 本稿之外的完整首页视觉设计规范、动效和品牌视觉系统。

## 4. 目标用户与用户故事

唯一面向用户的角色是学生。

- 作为学生，我希望打开首页就看到拍照收录入口，不必先进入错题页面再找添加按钮。
- 作为学生，我希望拍下历史题后自动识别题干，改正识别错误后保存。
- 作为学生，我希望先保存题目照片，之后再补题目答案、教材单元和错因。
- 作为学生，我希望复习时快速选择答对、部分掌握、答错或不确定，并能用文字或图片记录原因。
- 作为学生，我希望选择题按题号和选项排版，点选后立即知道正误并看到已有解析。
- 作为学生，我希望在作者记录的错因下面写下自己的新思考，并在以后回看。
- 作为学生，我希望图片识题不准确或不可用时，仍能手动录入或只保存图片。

## 5. 关键流程

### 5.1 首页拍照快速收录

目标流程：从首页点击“拍照收录” → 拍摄或从相册选图 → 视觉模型识题并显示草稿 → 学生校对或跳过识题 → 保存。

当前流程目标：从首页点击“拍照/相册收录” → 拍摄或选图 → 在全新录题草稿中预览本次图片并自动上传识题 → 可编辑题面填入题干，学生校对后保存。识题失败时保留照片并提示重拍、重选或手动输入。新草稿不会带入上一条录题的题干、答案或分类；同一录题会话的上传失败重试保留本次内容。图片可移除、重新选择，答案与分类默认折叠为选填项。

图片应始终保留为原始附件。学生可在保存前补充题干，也可以接受“仅图片题目”先保存为草稿；教材单元、知识点、错因、正确答案和解析不应成为快速收录时的强制字段。

### 5.2 首页文字录入

首页 → 点击“文字录入” → 输入或粘贴题干 → 可选补充答案、解析、分类和错因 → 保存。

文字录入不依赖视觉模型服务；用户可以在后续编辑中补充图片。

### 5.3 复习评分与补充记录

学生提交练习后选择答对、部分掌握、答错或不确定；可以补充一段文字说明，也可以附上作答图片。图片 OCR 如可用，应先提取文字并展示可编辑结果。最终复习结果由学生确认，OCR 不直接修改评分结果。

## 7. 首页布局要求

首页以学生当天可执行的任务为主，建议从上到下排列：

1. **页面标题与个人信息：** 显示简洁问候和学生昵称，不让个人信息区域挤占主操作空间。
2. **今日复习卡片：** 显示待复习、逾期数量和“开始复习”入口；无任务时显示轻量空状态。
3. **快速收录主操作：** 使用清楚的“拍照收录”按钮；“文字录入”作为相邻的次级入口。
4. **最近错题或学习摘要：** 只展示少量近期内容，点击后进入完整错题列表。
5. **固定底部导航：** 延续现有首页、错题、练习、我的导航，避免加入家长/教师入口或重复菜单。

布局原则：

- 首屏首先回答“现在可以做什么”；拍题入口和待复习任务优先级最高。
- 主按钮文案明确表达动作，不只使用无文字图标。
- 采用清晰的字号、对比度、留白和卡片分组；避免多个同等醒目的彩色大卡片争抢注意力。
- 保持页面可滚动；长列表放在次级区域，不挤压主任务。
- 加载中、无错题、无到期任务、网络失败和图片识题失败均提供明确状态与下一步操作。
- 本稿不指定具体色值、插画或最终视觉稿；UI 定稿后另行验收。

## 8. 录入规则与内容处理

### 8.1 图片识题与排版

- 图片来自用户主动拍摄或选择。
- 原始图片作为题目附件保留；视觉模型生成的题面是可编辑草稿，与用户最终确认内容区分。
- 测试版由后端调用 DeepSeek Flash 模型 `deepseek-flash` 的对话补全接口；密钥只配置在后端本地 `application-local.yml`，不得写入小程序代码、前端配置或版本库。图片会发送给 DeepSeek 服务进行识题。
- 模型输出作为图片理解草稿：要求只依据图片可见内容整理题面，不能解题或补写答案、解析及模糊内容。视觉模型可能误读或遗漏，学生必须校对后保存。
- 空结果、有效字符过少或符号噪声占比过高时返回未识别状态，提示重新拍摄/选择图片；不能将空字符串或错误信息误当题目保存。
- 识别范围优先覆盖印刷体中文题面，尽可能保留章节标题、题号、题干、A-D 选项、答案和解析的层级与顺序；缺失字段保持缺失，不猜测补全。
- 手写识别、复杂表格和跨页题目不作为 P0 保证能力。
- 模型不得静默删除原图，也不得在用户确认前将草稿作为已确认题目保存。
- 识别文本作为可编辑 Markdown 源文本保存；录题页提供格式预览，错题详情和练习页显示排版后的题面。渲染仅支持小程序内置富文本标签，不执行识别文本里的原始 HTML 或脚本。
- 模型按题面结构生成 Markdown 层级；不得推测缺失题号、答案或解析。已有草稿可手动触发“整理排版”，且保留原始图片供学生校对。

### 8.2 评分和复习结果

- 练习时，题面包含选项和明确标准答案的选择题使用点选即时反馈：学生点击选项后显示正确/错误、标准答案及已录入解析。没有明确答案时不自动判分，要求学生自评；主观题继续使用答对、部分掌握、答错、不确定等结果选择。
- 选择题判定和解析仅依据学生保存的题目内容，不由图片识题模型推断答案。
- 已录入的题型和错因显示在解析下方，作为作者当时的错题记录；未填写时不显示空字段。
- 学生可在答题反馈区或错题详情为题目（可选关联子题号）保存新的思考与反思；每次保存保留为一条独立记录，之后可在错题详情按时间回看。
- 结果说明可使用文字；图片为可选附件。
- 图片识题只生成录入候选题面，学生可修正；模型不判断练习作答正确性。
- 历史材料题和论述题由学生自评；若未来增加评分标准或自动评分，需单独评审、给出依据并保留人工修改入口。

### 8.3 历史信息

- 学科固定为历史，不显示其他学科选择器。
- 单元、课时、历史人物、事件、朝代、概念和错因可在快速保存后补充。
- 默认一次录入一题；多题批量处理属于 P1。

## 9. 建议性能与易用性目标（待评审）

以下是用于首轮原型评审的建议目标，不作为已批准的项目指标：

- 从首页到打开相机或相册：一次点击。
- 选图后到保存一条基础题目草稿：不超过 3 个主要确认动作。
- 在约定测试网络下，从图片上传完成到识题草稿可编辑：P95 不超过 5 秒；应单独记录超时和失败率。
- 易用性试测中，至少 4/5 名目标学生能在 5 秒内找到拍照入口。
- 典型单题录入的中位用时目标不超过 30 秒；需要人工校对的题目另外记录校对时间，不把模型等待隐藏在统计之外。
- 上述时间指标应先用原型试测校准，再写入正式 PRD 验收门槛。

## 10. 验收场景

1. 学生从首页一次点击进入拍照/相册；选择历史题图片后能看到原图预览并触发上传识别。
2. 视觉模型识题成功时，章节、题号、题干、选项及图片中可见的答案/解析按层级排版，显示在可编辑草稿中；模型不得自行解题或补写图片没有的内容。学生校对并保存后，重新打开详情可看到确认后的题目文字和原图。
3. 视觉模型未返回清晰题目内容时，显示“未识别到清晰题目，请重新拍摄或选择图片”；照片不丢失，学生可重试、换图、手动输入或仅保存图片草稿。
4. DeepSeek API Key 未配置、无效或服务超时时显示配置/网络错误提示，不返回伪造识别内容；前端包和小程序请求中看不到 API Key。
5. 选择不支持的图片格式或超过 10MB 的图片时显示可理解的格式/大小提示；本机草稿和图片不丢失。
6. 学生可直接粘贴题干创建文字题，不必先拍照或等待图片识题。
7. 学生复习时可选择结果、输入文字说明或添加作答图片；OCR 文本校对完成前不会改变复习判定。
8. 学生可跳过教材、知识点、错因和答案等次要字段，稍后编辑补充。
9. 首页首屏能清楚区分拍照收录、待复习和错题列表；无任务和网络异常时均有明确说明。
10. 连续点击保存或上传重试不会产生重复题目；保存或上传失败后可在当前录题草稿中重试。
11. 完成或暂存一条题目后再次从首页拍摄新照片，录题页只显示新照片；题干、答案、章节、知识点和错因等字段均为空或默认值，不沿用上一条记录。
12. 图片识题结果保留可编辑文本；录题预览、错题详情、练习题面和答案订正区均按支持的 Markdown 格式排版，普通文字和选项仍可读。
13. 对尚未整理的识别草稿点击“整理排版”后，章节、题目和答案层级更清楚；重复操作不重复添加格式标记，原识别词句不被自动补写或删除。
14. 有明确选项及标准答案的选择题，点击任一选项后立即看到正误；答错时标出正确选项，并显示已有解析。没有标准答案的题目不得自动猜答案。
15. 题型、错因只在录题时有填写的情况下显示在解析下方；未填写时页面不留空占位。
16. 学生在练习反馈区保存随笔后，可在对应错题详情看到内容、保存时间和所属子题号；再次保存形成新记录，不覆盖旧记录。
17. 未执行数据库更新脚本时，反思接口应明确报错；执行 `database/upgrade-student-reflections.sql` 并重启后端后，练习页和错题详情均可保存、读取学生随笔。

## 11. 数据和实现影响（供后续编码参考）

- 题目仍归当前学生账号所有；客户端不能自行指定所有者。
- 建议记录录入来源（拍照、相册、文字）、识题状态（未处理、成功、失败、待确认）以及识题草稿和最终确认内容。
- 图片识题候选内容与学生确认后的题目内容应可区分，便于校对及问题排查。
- 题目图片继续使用受登录态保护的附件存储；图片上传和题目保存需支持失败恢复及幂等处理。
- 图片识题 API 属于后端 `recognition` 模块；题目保存仍归 `question`，照片永久附件仍归 `storage`。识题本身不创建题目，不需要数据库表变更；原图在学生保存错题时再走现有附件接口。
- 学生随笔归属后端 `question` 模块，使用 `question_reflections` 独立记录题目、学生、子题号、内容和创建时间；已有数据库需先执行 `database/upgrade-student-reflections.sql`，新建数据库则使用更新后的 `database/schema.sql`。
- 与后端 DDD 模块的建议归属：recognition 负责 DeepSeek Flash 适配及题面可用性判断，question 负责题目录入，storage 负责永久图片附件，taxonomy/history catalog 负责历史分类，dashboard 负责学生首页摘要。

## 12. 待确认问题

1. 截图中的“评分支持文本图片 OCR”具体指：OCR 识别题目、识别学生作答，还是识别后自动评分？本稿暂定为题目/作答文字提取，学生校对并自行选择复习结果。
2. OCR 首版只处理印刷体中文题干，还是需要同时识别图片中的标准答案、选项和解析？
3. 截图中的“扫描”是否仅指相机拍照，还是需要自动裁边/透视矫正？一次拍照是否默认一张图对应一道题？多题拆分作为 P1。
4. 首版历史分类覆盖初中、高中，还是先选一个学段与教材版本？
5. 首轮易用性测试后，是否接受第 9 节的点击数、OCR 时延和录入用时作为正式目标？
