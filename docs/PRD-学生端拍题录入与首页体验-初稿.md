## 实现进度（2026-10-20）

**已编码，待学生真机验收：** 首页一键打开相机/相册；单题最多选择4张原图；录题页支持预览、移除和重新选择；题干、答案和分类可后补，图片可先保存为错题草稿；新建记录默认使用历史学科；首页显示待复习、近期学习摘要和最近收录的错题。每次新拍照或新建文字题使用独立草稿，题干、答案和分类从空白/默认历史状态开始，不读取上一次录题；同一录题会话的失败重试仍可恢复本次草稿。图片上传继续使用请求幂等机制。

**仍未实现：** 图片 OCR 识别及可编辑识别草稿；复习结果图片 OCR；自动裁边或透视矫正。当前没有接入 OCR 服务，拍照后可手动录入文字，也可只保存图片。OCR 服务选型和调用配置确认后再编码，当前流程不会把学生图片发送到第三方 OCR 服务。

## 1. 背景与目标

学生需要快速把历史题目加入错题本。当前产品已支持拍照/相册和错题记录，但录入步骤、OCR 和首页信息层级还需要按“快、清楚、容易找到”进一步设计。

本次目标：

1. 从首页快速进入拍题或文字录题。
2. 用 OCR 减少重复打字；识别结果必须能由学生校对。
3. 让学生可以先保存题目，再补充非必填分类和订正信息。
4. 首页突出当前最重要的学习任务和录题动作，降低寻找入口的时间。
5. 复习评分可用文字记录；需要时可添加图片并通过 OCR 辅助提取文字。

## 2. 范围与边界

### 2.1 本稿范围

- 首页快捷录题入口和首页信息层级。
- 相机拍照和相册选择题目；若“扫描”指自动裁边或透视矫正，则需先确认后纳入。
- OCR 识别题干及可选答案文字，生成可编辑草稿。
- 手动文字录题和 OCR 失败后的备用流程。
- 复习结果、自评文字和图片附件的录入体验。
- 录入耗时、点击步骤和 OCR 响应的建议验收指标。

### 2.2 本稿不包含

- 家长端、教师端或多角色工作台。
- 多学科管理；当前只针对历史。
- 批量多题识别、复杂图片标注、AI 解题或自动生成答案。
- 自动评判材料分析题、论述题或手写答案的正确性。
- 本稿之外的完整首页视觉设计规范、动效和品牌视觉系统。

| 评分支持文本图片 OCR | 复习结果可以文字记录；图片中的题目或作答文字可用 OCR 提取为草稿，学生确认后保存 |

| 添加错题便利性，主要是时间短、快 | 允许图片先保存，分类和错因等次要信息可后补；关键流程减少必填项和页面跳转 |

**待确认的用词：**“评分支持文本图片 OCR”可能表示“作答文字或图片可以录入并 OCR”，也可能表示“识别后自动评分”。本稿按前一种方式设计：OCR 负责提取可编辑文字，不自动判对错。历史材料题和论述题需要结合语义与评分标准，自动评分暂不纳入本稿。

## 4. 目标用户与用户故事

唯一面向用户的角色是学生。

- 作为学生，我希望打开首页就看到拍照收录入口，不必先进入错题页面再找添加按钮。
- 作为学生，我希望拍下历史题后自动识别题干，改正识别错误后保存。
- 作为学生，我希望先保存题目照片，之后再补题目答案、教材单元和错因。
- 作为学生，我希望复习时快速选择答对、部分掌握、答错或不确定，并能用文字或图片记录原因。
- 作为学生，我希望 OCR 不准确或不可用时，仍能手动录入或只保存图片。

## 5. 关键流程

### 5.1 首页拍照快速收录

目标流程：从首页点击“拍照收录” → 拍摄或从相册选图 → OCR 处理并显示草稿 → 学生校对或跳过 OCR → 保存。

当前已编码流程：从首页点击“拍照/相册收录” → 拍摄或选图 → 在全新录题草稿中预览本次图片 → 手动输入题干或先保存图片草稿。新草稿不会带入上一条录题的题干、答案或分类；同一录题会话的上传失败重试保留本次内容。OCR 仍待接入；图片可以移除、重新选择，答案与分类默认折叠为选填项。

图片应始终保留为原始附件。学生可在保存前补充题干，也可以接受“仅图片题目”先保存为草稿；教材单元、知识点、错因、正确答案和解析不应成为快速收录时的强制字段。

### 5.2 首页文字录入

首页 → 点击“文字录入” → 输入或粘贴题干 → 可选补充答案、解析、分类和错因 → 保存。

文字录入不依赖 OCR 服务；用户可以在后续编辑中补充图片。

### 5.3 复习评分与补充记录

学生提交练习后选择答对、部分掌握、答错或不确定；可以补充一段文字说明，也可以附上作答图片。图片 OCR 如可用，应先提取文字并展示可编辑结果。最终复习结果由学生确认，OCR 不直接修改评分结果。

## 6. 功能需求

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| CAP-01 | P0 | 首页提供显眼的“拍照收录”主入口 | 从首页一次点击即可打开相机/相册选择 |
| CAP-02 | P0 | 支持相机拍照和相册选图 | 用户可预览、重拍或更换图片；保留原图。“扫描”是否要求自动裁边/矫正待确认 |
| CAP-03 | P0 | 支持以图片先建草稿 | 至少一张题目图片即可保存本地草稿；文字、答案、错因和分类可后补 |
| CAP-04 | P0 | OCR 识别题目文字 | 识别结果显示在可编辑字段中；用户确认前不得覆盖题目最终内容 |
| CAP-05 | P0 | OCR 失败或低置信度时可人工处理 | 显示失败/待确认提示；可重试、手动输入或仅保留图片 |
| CAP-06 | P0 | 提供直接文字录入 | 可输入或粘贴题干；OCR 不可用时仍可完成录题 |
| CAP-07 | P0 | 快速录题不强制填写次要信息 | 教材单元、知识点、错因、参考答案和解析均可先跳过并稍后补充 |
| CAP-08 | P0 | 复习结果支持文字说明及图片附件 | 学生先选择复习结果，再输入文字或添加图片；图片识别文本供学生校对 |
| CAP-09 | P0 | 首页突出待复习和快速收录 | 首屏能区分主操作、待复习任务和错题列表入口 |
| CAP-10 | P0 | 草稿隔离与重试保护 | 每次新拍照/新建创建独立草稿，不带入上一条草稿字段；本次录题保存或图片上传失败时可在当前草稿重试；重复点击保存不生成重复题目 |
| CAP-11 | P1 | 图片 OCR 质量与识别辅助 | 低置信度字段可见提示；支持只重做识别或继续手动修改 |
| CAP-12 | P1 | 多题批量识别 | 一张或多张照片拆分为多道题；有独立排序与确认流程，本稿不要求首版实现 |

## 7. 首页布局要求

首页以学生当天可执行的任务为主，建议从上到下排列：

1. **页面标题与个人信息：** 显示简洁问候和学生昵称，不让个人信息区域挤占主操作空间。
2. **今日复习卡片：** 显示待复习、逾期数量和“开始复习”入口；无任务时显示轻量空状态。
3. **快速收录主操作：** 使用清楚的“拍照收录”按钮；“文字录入”作为相邻的次级入口。
4. **最近错题或学习摘要：** 只展示少量近期内容，点击后进入完整错题列表。
5. **固定底部导航：** 延续现有首页、错题、练习、我的导航，避免加入家长/教师入口或重复菜单。

布局原则：

- 首屏首先回答“现在可以做什么”；拍题入口和待复习任务优先级最高。
- 主按钮文案明确表达动作，不只使用无文字图标。
- 采用清晰的字号、对比度、留白和卡片分组；避免多个同等醒目的彩色大卡片争抢注意力。
- 保持页面可滚动；长列表放在次级区域，不挤压主任务。
- 加载中、无错题、无到期任务、网络失败和 OCR 失败均提供明确状态与下一步操作。
- 本稿不指定具体色值、插画或最终视觉稿；UI 定稿后另行验收。

## 8. 录入规则与内容处理

### 8.1 图片和 OCR

- OCR 输入图片来自用户主动拍摄或选择。
- 原始图片作为题目附件保留；OCR 文本是可编辑草稿，与用户最终确认内容区分。
- 识别范围优先覆盖印刷体中文题干；选项、年代、人物名、材料段落和答案等字段按识别能力逐步扩展。
- 手写识别、复杂表格和跨页题目不作为 P0 保证能力。
- OCR 不得静默删除原图，也不得在用户确认前作为标准答案保存。

### 8.2 评分和复习结果

- P0 继续使用答对、部分掌握、答错、不确定等结果选择。
- 结果说明可使用文字；图片为可选附件。
- OCR 只提取图片中的候选文字，学生可修正；OCR 本身不判断作答正确性。
- 历史材料题和论述题由学生自评；若未来增加评分标准或自动评分，需单独评审、给出依据并保留人工修改入口。

### 8.3 历史信息

- 学科固定为历史，不显示其他学科选择器。
- 单元、课时、历史人物、事件、朝代、概念和错因可在快速保存后补充。
- 默认一次录入一题；多题批量处理属于 P1。

## 9. 建议性能与易用性目标（待评审）

以下是用于首轮原型评审的建议目标，不作为已批准的项目指标：

- 从首页到打开相机或相册：一次点击。
- 选图后到保存一条基础题目草稿：不超过 3 个主要确认动作。
- 在约定测试网络下，从图片上传完成到 OCR 草稿可编辑：P95 不超过 5 秒；应单独记录超时和失败率。
- 易用性试测中，至少 4/5 名目标学生能在 5 秒内找到拍照入口。
- 典型单题录入的中位用时目标不超过 30 秒；需要人工校对的题目另外记录校对时间，不把 OCR 等待隐藏在统计之外。
- 上述时间指标应先用原型试测校准，再写入正式 PRD 验收门槛。

## 10. 验收场景

1. 学生从首页一次点击进入拍照/相册；选择历史题图片后能看到原图预览。
2. OCR 成功时，题干出现在可编辑草稿中；学生修改内容并保存后，重新打开详情可看到确认后的题目文字和原图。
3. OCR 失败或不可用时，学生可重试、手动输入或只保存图片草稿，不会丢失照片。
4. 学生可直接粘贴题干创建文字题，不必先拍照或等待 OCR。
5. 学生复习时可选择结果、输入文字说明或添加作答图片；OCR 文本校对完成前不会改变复习判定。
6. 学生可跳过教材、知识点、错因和答案等次要字段，稍后编辑补充。
7. 首页首屏能清楚区分拍照收录、待复习和错题列表；无任务和网络异常时均有明确说明。
8. 连续点击保存或上传重试不会产生重复题目；保存或上传失败后可在当前录题草稿中重试。
9. 完成或暂存一条题目后再次从首页拍摄新照片，录题页只显示新照片；题干、答案、章节、知识点和错因等字段均为空或默认值，不沿用上一条记录。

## 11. 数据和实现影响（供后续编码参考）

- 题目仍归当前学生账号所有；客户端不能自行指定所有者。
- 建议记录录入来源（拍照、相册、文字）、OCR 状态（未处理、成功、失败、待确认）以及识别草稿和最终确认内容。
- OCR 原始候选文本与学生确认后的题目内容应可区分，便于校对及问题排查。
- 题目图片继续使用受登录态保护的附件存储；图片上传和题目保存需支持失败恢复及幂等处理。
- 现有题目创建和附件 API 可作为实现检查入口；是否新增 OCR 服务/API、OCR 服务选型和数据库字段以技术设计及后续 SQL 更新脚本为准，本稿不预设具体接口。
- 与后端 DDD 模块的建议归属：question 负责题目录入用例，storage 负责图片附件，taxonomy/history catalog 负责历史分类，dashboard 负责学生首页摘要。

## 12. 待确认问题

1. 截图中的“评分支持文本图片 OCR”具体指：OCR 识别题目、识别学生作答，还是识别后自动评分？本稿暂定为题目/作答文字提取，学生校对并自行选择复习结果。
2. OCR 首版只处理印刷体中文题干，还是需要同时识别图片中的标准答案、选项和解析？
3. 截图中的“扫描”是否仅指相机拍照，还是需要自动裁边/透视矫正？一次拍照是否默认一张图对应一道题？多题拆分作为 P1。
4. 首版历史分类覆盖初中、高中，还是先选一个学段与教材版本？
5. 首轮易用性测试后，是否接受第 9 节的点击数、OCR 时延和录入用时作为正式目标？
