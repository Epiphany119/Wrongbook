## 1. 产品概述

### 1.1 产品定位

本产品是面向中小学生的历史学科专用错题本。学生把历史作业、测验和试卷中的错题整理为个人学习记录，通过历史知识分类、练习和间隔复习持续订正。产品不提供多学科切换，也不依赖完整公共题库。家长通过授权关系了解孩子的学习摘要，教师通过班级和作业范围开展历史复习协作。

产品目标形态是一款微信小程序内的三个角色工作台：学生、家长和教师。三个工作台共用应用和身份基础，但各自展示不同任务和数据范围。

### 1.2 产品目标

1. 降低学生收录历史错题、补充订正和标注历史知识点的成本。
2. 支持按教材单元、课时、时代、人物、事件、概念、题型和错因检索历史错题。
3. 通过历史专项练习和间隔复习记录学生的订正过程。
4. 让家长了解必要的学习摘要，让教师按班级和已布置任务提供帮助。
5. 保护学生的题目照片、个人笔记和学习档案；家长和教师只访问明确授权的范围。

### 1.3 核心学习闭环

学生收录历史错题 → 补充原答、参考答案和订正 → 关联教材单元、知识点或历史要素 → 安排练习与复习 → 记录结果 → 更新下次复习时间 → 学生回看个人进度，家长或教师在授权范围内查看相应摘要或任务结果。

### 1.4 成功指标

- 学生可以独立完成一题从收录、订正、历史分类、练习到复习记录的完整流程。
- 学生能按历史教材单元、知识点、题型和错因找到错题，练习时答案不会提前显示。
- 家长只能看到授权孩子的学习摘要；教师只能看到自己班级和已布置任务范围内的数据。
- 每次练习的结果、时间和下一次复习建议可回看。
- 上传失败、重复提交、权限撤销和版本冲突不会导致数据泄露、重复创建或静默覆盖。

首版不以练习数量、单次正确率或自动生成内容作为学生掌握程度的唯一判断。

## 2. 用户与使用场景

| 角色工作台 | 主要任务 | 默认访问边界 |
| --- | --- | --- |
| 学生 | 收录和维护自己的历史错题；按历史单元和错因练习；查看复习计划与个人进度；管理分享授权 | 管理本人错题、答案、照片和复习记录 |
| 家长或监护人 | 绑定一个或多个孩子；查看复习完成情况、到期数量和单元级学习摘要；协助关注复习计划 | 默认只看学习摘要；题目详情须由学生分享或另行授权；不能修改学生原始错题 |
| 教师 | 创建班级；布置历史单元复习任务；查看班级完成汇总；对学生提交的任务作答反馈 | 仅访问自己班级和已布置任务；不能检索学生的私人错题本 |
| 管理员 | 维护分类和帮助信息，处理服务问题 | 属于内部运营角色，不作为第四个用户工作台；访问学生原始数据须有业务理由并留下审计记录 |

账号可以同时具有多个角色，例如学生也可以是家长。进入不同工作台时按当前角色展示相应功能；角色身份本身不自动授予对某个学生或班级数据的访问权，仍需有效关系和资源范围。

### 2.1 主要场景

- 学生拍摄一道历史材料题，补充自己的答案、参考答案、订正说明和所属教材单元。
- 学生按朝代、人物、事件或知识点整理错题，通过时间线排序或人物事件匹配进行复习。
- 家长绑定孩子后查看近期完成情况和薄弱单元摘要，帮助安排复习时间。
- 教师创建班级并布置某单元复习任务，查看班级完成率及已提交学生的任务作答。
- 家长解除绑定或学生离开班级后，对应访问权限及时失效。

## 3. 产品范围与版本规划

### 3.1 首阶段 P0：学生历史学习闭环

历史学科固定为唯一面向用户的学科；完成学生个人档案、历史错题收录与维护、历史分类检索、专项练习、复习安排、学习看板、个人数据导出删除和基本权限隔离。当前已有的通用学科分类代码作为基础设施，不在产品界面提供多学科选择。

### 3.2 第二阶段 P1：家长工作台与学生效率增强

增加家长和学生绑定、多个孩子切换、学习摘要和授权撤销；同时可逐步实现 OCR 辅助录入、批量处理、图片标注、订阅提醒、智能提示与历史复习卷导出。家长默认只能查看摘要，明细查看须有明确授权。

### 3.3 第三阶段 P2：教师工作台与个性化扩展

增加班级、邀请码、历史单元复习任务、任务结果汇总和教师反馈；样本充分后再评估个性化复习推荐。教师访问严格限制在所属班级和已布置任务范围。

### 3.4 首版明确不包含

多学科错题管理、完整公共题库、自动替代教师判断的材料题或论述题评分、默认向家长或教师公开学生全部题目、未经学生确认的 AI 生成答案、正式线上部署能力。智能生成内容只能作为辅助建议，学生需要自行核对。

## 4. 当前技术与运行基线

当前项目的实际实现决策如下：

- 前端：微信原生小程序，在微信开发者工具中开发。
- 后端：JDK 17、Spring Boot，采用 DDD 风格模块化单体，在 IDEA 中运行。
- 结构化数据：本机 MySQL；数据库建表与升级脚本由项目成员手动执行。
- 图片附件：由后端保存在运行后端的电脑本地目录，通过需要登录态的接口访问。
- 真机开发联调：电脑和手机连接同一手机热点，小程序使用电脑当时的热点 IP 访问后端。
- 当前身份：本地开发登录，便于个人真机联调；这不是生产环境身份认证。
- 当前存储与联调只适用于本地开发，不代表已经具备云端同步、远程可用性、生产备份或公网部署能力。

原始需求文档建议采用微信小程序、Node.js 云函数、CloudBase 云数据库和云存储。该建议与项目现行的 Java、MySQL、本地文件存储决策不同；开发和维护以本节列出的现行基线为准。若未来改为远程部署或多设备正式使用，应另行确定部署、身份认证、文件存储、备份和同步方案。

用户已决定当前测试阶段不启用微信授权登录。正式发布前需重新评审生产身份认证方式与微信平台要求；在此之前，本地开发登录不得用于公网生产服务。

产品采用一款小程序承载学生、家长、教师三个角色工作台，不先拆成三套独立应用。当前开发登录可继续用于联调；多角色账号、工作台切换和家长/教师关系授权属于待开发能力。原始需求中的多学科分类仅作为通用分类技术背景，产品决定以历史作为唯一学科。

## 5. 开发进度与功能清单

本节是项目功能状态的唯一维护区，所有功能都应归入以下两个区域，并按业务模块保持对应关系。这里记录的是代码中已具备的能力和仍需实现或确认的事项。

### 5.1 已完成区域

以下能力已有当前版本实现。这里的“完成”仅覆盖列出的范围，不代表生产部署、云端服务或其他未列明能力已经完成。

#### 身份与个人档案

- 本地开发登录，可为真机联调建立开发身份。
- 学习档案读取和更新，包含昵称、头像、年级、学期、教材版本等字段。
- 头像上传与读取。
- 当前用户的个人数据 JSON 导出，以及账号和关联数据删除接口。

#### 错题管理与附件

- 错题创建、详情读取、编辑、归档、恢复和回收站查询。
- 错题列表关键词搜索、分页，以及学科、章节、错因、日期、状态和到期情况等查询条件。
- 题目照片上传，并通过登录态接口读取本机保存的附件。
- 小程序本机题目草稿保存。
- 创建请求幂等处理和编辑版本校验，降低重复创建与静默覆盖风险。

#### 分类与标签

- 已有通用学科、章节、知识点查询。
- 用户新增个人章节和知识点。
- 错题分类关联及个人标签能力。
- 以上为当前代码基础能力；历史专用分类和固定单学科产品体验仍列在未完成区域。

#### 练习、复习与看板

- 复习事件记录，包含结果、信心或耗时等复习信息。
- 1、3、7、14 天复习间隔策略及连续正确后更新掌握状态的规则。
- 练习会话创建和逐题提交；提交前返回题目内容，提交后提供答案与订正内容，并记录复习结果。
- 学习看板接口，提供待复习、逾期、近期正确率、重复错误和学科趋势等数据。

#### 权限、反馈与项目结构

- 开发身份下的用户数据隔离；题目附件通过服务端登录态读取。
- 用户问题反馈接口和健康检查接口。
- 后端按 identity、profile、taxonomy、question、review、practice、dashboard、storage、feedback、common 等业务模块组织，采用 DDD 风格模块化单体。
- 已完成一次手机热点下的小程序真机联调；此项仅代表本地开发环境联调可用。

### 5.2 未完成区域

未完成区域同时容纳尚未实现、只完成一部分、尚未确认验收口径，以及已规划但未排期的需求。新功能一律先登记在这里，写明所属模块、优先级、需求范围和验收条件。实现后先核对验收条件；全部满足后，将条目移到“已完成区域”的对应模块。部分完成时拆分已交付部分与剩余部分，不把整个条目标记为完成。

#### 身份与个人档案

- **P0/P1/P2 分期：角色工作台。** 一款小程序根据有效角色展示学生、家长或教师工作台；同一账号可拥有多个角色，但角色切换不自动获得数据访问权。
- **P0 待实现：开发态多角色联调。** 提供可控的测试账号或开发态角色切换，用于验证学生、家长、教师权限；不加入微信授权弹窗。
- **上线前待决：生产身份认证。** 当前仅使用本地开发登录。用户已决定测试阶段不启用微信授权登录；是否采用微信登录或其他生产认证方式，需在正式上线前另行评审，不应为了当前联调擅自加入授权弹窗。
- **验收条件：** 明确生产身份、凭据管理、会话有效期和账号注销流程；开发登录只能在开发环境开启。

#### 历史学科专用化

- **P0 待实现：固定历史单学科。** 小程序不提供多学科选择；题目创建、筛选、练习和看板均以历史为唯一学科。后端写入时拒绝非历史学科数据，读取时只返回历史错题；不能只依赖前端隐藏选择器。
- **P0 待实现：历史教材分类。** 分类建议为学段、年级、学期、教材版本、册、单元、课时和知识点；具体可用层级以选定教材为准。
- **P0 待实现：历史要素标签。** 支持按时代/朝代、人物、事件、地点、制度/概念、史料来源等维度标注；标签可逐步补充，不要求首版建设复杂知识图谱。
- **P0 待实现：历史题型和错因。** 题型覆盖时间排序、人物事件匹配、材料分析、因果分析、历史比较和地图题；错因可覆盖年代混淆、人物/事件混淆、因果不清、材料提取错误、史实记忆不完整、论述证据不足。
- **P1 可选增强：历史专项练习。** 逐步增加时间线排序、人物事件匹配、单元回顾等练习；材料分析和论述题由学生自评或教师反馈，不自动给出未经验证的标准评分。
- **待决事项：** 首版覆盖初中、高中还是其中一个学段；具体教材版本、年级范围和分类数据来源。
- **验收条件：** 前端只有历史学科入口；错题可关联选定教材和历史要素；历史筛选在创建、列表、练习和看板中保持一致。

#### 错题管理与图片

- **P0 待核实：** 题目照片裁剪、旋转和压缩是否已达到可用体验；未完成或未验收的部分继续留在本区域。
- **P1 OCR 辅助录入：** 展示识别草稿，学生确认或修改后才保存；识别失败可手动录入，并保留原图。
- **P1 批量收录：** 支持连续拍摄、多题排序、上传进度和失败重试；疑似重复只提示，不自动合并。
- **P1 图片标注：** 支持高亮、遮盖或短批注；标注作为新版本保存，原图可回看。
- **验收条件：** 上传失败后可重试且不会重复生成附件；识别或标注结果可由用户核对，不覆盖原始题目内容。

#### 分类、检索与复习

- **P0 待补充验收：** 明确一题关联多个知识点、年级与教材章节映射、分类调整时关联错题的处理方式；只对未完成或未确认的子项建立开发任务。
- **P0 待补充验收：** 核对复习队列、详情时间线、筛选条件与排序在小程序页面上的完整体验；后端已有接口的能力不重复记为新功能。
- **验收条件：** 分类变更不会无提示丢失题目关联；练习和复习历史可回看；练习提交前不展示答案。

#### 学习看板与学习计划

- **P0 待补充验收：** 确认各指标的时间范围、样本数、分母和“重复错误”口径，并确保页面有必要说明。
- **P1 学习计划与提醒：** 根据每日目标与到期复习生成任务清单；微信订阅消息仅在用户主动授权后发送，提供关闭和安静时段设置。
- **验收条件：** 看板数据可由题目与复习记录复算；样本不足时明确显示，不据此作过度结论；提醒授权可关闭。

#### 离线、同步与数据安全

- **P0 待实现：** 完整的失败上传队列、可恢复的编辑冲突处理和用户可理解的重试反馈。目前草稿保存在小程序本机，已有幂等键和版本校验，但尚不等于完整离线同步。
- **正式部署待办：** 远程数据库、附件存储、备份与恢复、清理策略、环境隔离和运行监控。当前 MySQL 与上传文件保存在本机，不具备云端同步或异地备份能力。
- **验收条件：** 失败或冲突时保留用户内容；重复操作不生成重复数据；完成备份恢复演练；未授权用户无法读取他人题目、头像或导出文件。
- **待决事项：** 回收站保留期限、账号删除后的清理时限、导出格式版本，以及正式环境的远程存储和备份责任。

#### 家长工作台、教师工作台与智能能力

- **P1 家长工作台：** 家长通过短时邀请与一个或多个孩子建立关系；学生确认绑定，依法需要监护人同意的场景另设相应同意流程。家长默认查看到期数量、练习完成情况和单元级学习摘要。
- **P1 家长权限：** 默认不开放题目照片、学生笔记和完整答案；学生分享特定错题或范围后，家长才可只读查看。家长不能改写或删除学生原始错题；关系可暂停或撤销。
- **P2 教师工作台：** 教师创建班级邀请，学生主动加入；教师按历史教材单元布置复习任务，查看班级完成汇总。
- **P2 教师权限：** 教师可查看自己已布置任务的提交情况和学生对此任务提交的作答，可添加独立的教师反馈；不得搜索学生私人错题本，不得修改原始答案和个人笔记。退出班级或撤销关系后访问及时失效。
- **P1 智能提示与相似题：** 用户主动触发，清楚标注生成内容并提醒核对；不得覆盖标准答案或用户订正。
- **P1 复习卷导出：** 按历史单元、错因或日期生成练习页，支持无答案版和答案解析版，导出前预览。
- **P1 运营配置与监控：** 管理分类、复习参数和帮助信息；监控接口耗时、上传失败和错误类型，减少不必要的个人信息。
- **P2 个性化复习推荐：** 在样本充分时推荐复习次序并说明原因，学生可调整，推荐不以分数为唯一目标。
- **验收条件：** 家长与教师的数据范围由服务端逐请求校验；访问关系可撤销并及时生效；教师仅访问授权班级和任务；教师反馈与学生原始作答分开保存。
- **待决事项：** 未成年人及家庭/学校关系的具体授权流程；OCR、AI 和订阅消息的服务方、成本、数据处理方式与授权交互。

#### 帮助与反馈

- **待补充：** 完善录题说明、常见问题和复习规则说明；反馈默认不附带题目照片，诊断材料由用户主动选择。
- **验收条件：** 用户能从小程序找到帮助和反馈入口；反馈所附内容在发送前可见并由用户确认。

### 5.3 状态维护规则

- 后续新增功能先放在“未完成区域”，归入对应模块并写明优先级和验收条件。
- 只有实现范围达到对应验收条件后，才将已完成条目移入“已完成区域”的对应模块。
- 部分完成时拆分条目：已经达到验收条件的子项移入“已完成区域”，其余子项继续留在“未完成区域”。
- 需求取消或延期时，在未完成条目中注明决定与原因，不删除历史上下文。
- 功能状态以当前代码和实际验收为准；仅有接口、设计稿或计划不代表功能已完成。


## 6. 关键业务规则

### 6.1 错题状态

- 新收录：已保存但尚未完成足以进入掌握状态的复习。
- 待复习：需要继续订正或按计划再次练习。
- 已掌握：达到当前版本的连续正确规则。
- 已归档：用户暂不纳入日常复习，但记录仍可查找或恢复。
- 回收站：用户删除后的可恢复状态；其保留期限和彻底清除策略在正式部署前明确。

### 6.2 复习结果

每次复习应保留题目 ID、用户 ID、结果、复习时间、信心和耗时（有值时）、结果对应的下次复习时间和规则版本。对客观题只有在评分规则明确时才自动判分；主观题由学生自评。

### 6.3 数据归属与版本

每条个人错题、复习记录和附件都应能追溯所属用户。服务端从已验证的身份上下文取得用户标识。创建请求应支持幂等处理；修改请求应携带版本或等效并发控制信息。

### 6.4 历史分类

历史是产品唯一面向用户的学科。分类以选定学段和教材为主线，历史事件、人物、时代、地点、制度/概念和史料来源作为可组合的标注维度；首版使用可维护的分类与标签，不要求实现完整知识图谱。分类变更时不能无提示地丢失错题关联；需定义迁移、解除关联或停用策略。初高中及教材版本须在开发该分类数据前确认。

## 7. DDD 模块边界参照

当前后端为模块化单体，按业务能力划分模块。新功能优先归入对应业务模块；跨模块协作通过应用层用例或明确接口完成，避免控制器直接依赖其他模块的数据库实现。表中标注“规划”表示尚未实现。

| 模块 | 主要职责 | 当前代码边界 |
| --- | --- | --- |
| identity / authorization | 开发身份、角色声明、会话上下文和请求级权限检查 | identity（多角色授权为规划） |
| profile | 学习档案、头像、导出与删除 | profile |
| taxonomy / history catalog | 历史学段、教材、单元、课时和历史要素 | taxonomy（历史专用化为规划） |
| question | 错题内容、分类关联、搜索、归档与回收站 | question |
| review | 复习事件、复习计划与间隔规则 | review |
| practice | 练习会话、答题和练习结果 | practice |
| dashboard | 学生进度、家长摘要和班级任务汇总 | dashboard（家长/班级视图为规划） |
| family | 学生与监护人关系、邀请、授权范围和撤销 | 规划 |
| classroom / assignment | 班级成员、教师任务、学生提交和教师反馈 | 规划 |
| storage | 题目及头像等附件的上传和受控读取 | storage |
| feedback | 用户问题反馈 | feedback |
| common | 通用异常、配置、健康检查等横切能力 | common |

每个业务模块按需要拆分 interfaces、application、domain、infrastructure 等层。身份认证只确认当前账号，不代表该账号可以访问任意学生；家长访问需检查有效家庭关系和授权范围，教师访问需检查班级成员关系及任务范围。持久化与本地文件操作放在基础设施实现中。将来如改用云存储或远程数据库，应保留相同的访问控制语义。

## 9. 非功能需求

### 9.1 性能

在约定的测试网络和测试数据量下：首页首屏渲染 P95 目标不超过 3 秒，常规文本读写 API P95 目标不超过 2 秒。图片上传、下载及未来 OCR 的耗时分别统计，不与普通文本接口混算。测试时记录设备、网络和样本规模。

### 9.2 安全与隐私

- 所有业务接口执行身份验证和数据归属检查。
- 用户 ID、所有权和授权关系由服务端确定，不能由客户端自行声明。
- 图片和导出文件不得通过长期公开地址暴露。
- 数据库凭据、微信密钥和第三方服务密钥只能放在服务端配置中。
- 开发登录必须受环境配置保护，不用于生产服务。
- 家长访问必须校验有效的学生关系和授权范围；教师访问必须同时校验班级成员关系和任务范围；角色身份不能单独作为访问凭证。
- 学生撤销家长分享或退出班级后，对应访问应及时失效；教师查看个人任务答卷时应记录访问和反馈。
- 题目照片、个人笔记和原始答案默认不向家长或教师开放；教师反馈与学生原始内容分开保存。
- 面向未满十四周岁用户的个人信息处理，应按适用要求取得监护人同意并制定专门处理规则；不得把非必要信息授权作为使用基本学习功能的条件。参见[《个人信息保护法》第二十八条、第三十一条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)及[《未成年人网络保护条例》第三十二条](https://www.cac.gov.cn/2023-10/24/c_1699806932316206.htm)。

### 9.3 可靠性

- 保存操作返回明确成功或失败状态；失败时保留可恢复内容。
- 网络重试遵循幂等规则。
- 并发编辑提供版本冲突反馈。
- 正式远程环境需有备份、恢复演练、附件清理和故障排查流程。

### 9.4 可维护性

- 业务需求或复习规则变化时更新本文及相应接口、数据库升级脚本。
- 数据库变更提供可审阅的 SQL 脚本和执行说明；升级脚本说明适用版本与重复执行行为。
- 新业务功能遵循模块边界，避免未说明地跨模块读写表。
- 对错误响应、空数据、加载中和失败重试等状态保持一致的交互反馈。

## 10. 阶段验收标准

| 验收项 | 通过条件 |
| --- | --- |
| 历史单学科 | 用户界面只提供历史；创建、检索、练习和看板使用一致的历史分类，不出现其他学科入口 |
| 历史分类 | 错题可关联选定教材单元、知识点及历史要素；教材范围确认后，常用筛选可正常工作 |
| 学生学习闭环 | 学生可创建并编辑历史错题、完成练习、记录复习结果，并看到下一次复习安排 |
| 答案保护 | 练习提交前不返回或展示答案、解析和订正；提交后才提供核对信息 |
| 家长权限（P1） | 家长仅能访问已绑定且授权的孩子；默认显示摘要，不可读取未分享的题目照片、私有笔记或全量答案；解绑后访问失效 |
| 教师权限（P2） | 教师仅能访问本人班级和已布置任务；能查看该任务的学生提交并给独立反馈，不能浏览或修改学生私人错题 |
| 多角色隔离 | 一个账号可拥有多个角色；切换工作台不改变数据授权，服务端逐请求校验用户、关系和资源范围 |
| 用户隔离 | 两个独立开发身份不能读取或修改彼此的题目、档案和附件 |
| 复习规则 | 不同结果会按当前规则更新计划；掌握状态符合连续正确条件，规则版本可追溯 |
| 数据恢复 | 草稿可恢复；网络失败允许重试；重复提交不重复创建数据；冲突不会静默覆盖 |
| 统计一致 | 学生看板、家长摘要和班级汇总均注明范围与口径，可由相应记录复算 |
| 导出与删除 | 用户可导出自己的数据；删除操作覆盖约定范围内的个人数据及附件 |
| 图片访问 | 未授权用户无法读取其他用户的题目照片或头像文件 |
| 真机开发 | 在电脑和手机处于同一热点、后端运行且配置有效时，小程序可完成核心接口联调 |
| 性能 | 在约定环境执行测量并达到第 9.1 节目标，或记录偏差及改进计划 |

## 11. 开发顺序与交付建议

开发排期只从第 5.2 节“未完成区域”选择条目，不在其他章节维护第二份功能待办：

1. **第一阶段：学生历史学习闭环。** 固定历史单学科，确认目标学段和教材，完成历史分类、错题、练习、复习和学生进度。
2. **第二阶段：家长工作台。** 完成家庭绑定、授权范围、多个孩子切换、学习摘要和撤销权限。
3. **第三阶段：教师工作台。** 完成班级关系、历史单元任务、任务作答、班级汇总和独立教师反馈。
4. OCR、AI、提醒和个性化能力按第 5.2 节中的条目单独排期；未达到验收条件前保持在未完成区域。
