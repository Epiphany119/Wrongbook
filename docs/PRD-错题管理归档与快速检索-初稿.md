# 小 E 错题本 PRD：错题管理、归档与快速检索

| 项目 | 内容 |
| --- | --- |
| 版本 | 1.0 |
| 状态 | 已编码，待数据库升级与真机验收 |
| 需求编号 | 第二个需求 |
| 适用产品 | 小 E 错题本学生端（历史学科） |
| 需求来源 | 降低纸质错题整理成本；电子化保存；通过快速查询和归档管理长期积累的错题 |

## 1. 背景与问题

纸质错题本需要抄题、分类和翻找，整理与复习成本较高。学生需要把题目、原答、参考答案、错因、历史分类和练习记录集中保存在电子错题本中，之后能用关键词、分类和状态快速找到记录。对本需求而言，纸面减少和检索省时是产品价值；本需求不提供实际费用核算。

现有系统已有错题列表、部分筛选、分页、回收站及后端归档接口。需要补齐的重点是：明确“归档”和“移入回收站”的区别；让学生在列表中直接归档或恢复；让关键词检索覆盖题干以外的答案、解析和分类信息；让无结果、重置筛选和查询排序更容易理解。

## 2. 目标与指标

1. 让学生在一个页面管理未归档和已归档的历史错题。
2. 归档仅把记录从日常错题/练习范围中收起，保留记录和学习历史；学生可以随时恢复。
3. 学生可搜索题干、作答、参考答案、订正、解析、题型、错因、标签、章节或知识点。
4. 常见查询支持服务端筛选、分页和排序，避免一次加载全部记录。
5. 减少学生找回一题所需时间；在约 10,000 条文本错题的本地 MySQL 数据集上，关键词查询 API 的 P95 目标不超过 1 秒。该目标需在约定设备和数据集下测量，图片识别及附件传输耗时不计入。

## 3. 用户与范围

唯一用户为学生。学生只能管理和检索自己的历史错题。

### 本期包含

- 未归档列表与已归档列表切换。
- 搜索题目和记录文本，按状态、章节、错因、个人标签、日期、到期情况筛选。
- 最新收录、近期到期、最常错和搜索匹配度排序。
- 分页加载、匹配数量、无结果提示和清空筛选。
- 列表和详情中的归档/恢复操作，操作前二次确认。
- 搜索索引 SQL 升级脚本及初始化 schema 同步。

### 本期不包含

- 批量选择、批量归档或批量删除。
- 物理删除；需删除的数据继续使用独立回收站与恢复流程。
- 多设备云同步、公开分享、家长或教师协作。
- 费用统计或纸张消耗估算。
- 自动生成分类或自动合并重复题目。

## 4. 业务规则

### 4.1 记录范围

- 默认进入“未归档”列表；包含新收录、待复习和已通过记录，不包含已归档记录。
- “已归档”列表只显示已归档记录。
- 回收站是独立范围，不与已归档混为一处。
- 默认每页 20 条，继续滚动后请求下一页；总数由当前筛选条件计算。

### 4.2 归档与恢复

- 归档不删除题目、答案、解析、照片、分类、练习历史或学生随笔；归档题不进入默认列表和日常练习。
- 列表卡片和详情页提供归档操作；归档前显示确认提示。操作成功后更新列表和数量。
- 从已归档列表恢复后，记录回到未归档列表。状态根据保留的练习数据恢复：从未练习为“新收录”；有练习记录但未连续通过三次为“待复习”；连续通过三次为“已通过”。原有复习时间和历史记录保留。
- 归档记录若移入回收站，仍按回收站规则恢复，不把软删除恢复与取消归档混成一个操作。

### 4.3 检索与筛选

- 关键词覆盖题干、原作答、参考答案、订正、解析、题型、错因、来源、章节名、知识点名和个人标签。
- 支持筛选：未归档/已归档、新收录/待复习/已通过、历史章节、错因、标签、日期范围和“只看待复习”。
- 可清空关键词和所有筛选条件，回到默认未归档列表。
- 有筛选条件而无匹配记录时显示“没有找到符合条件的错题”和清空入口；空的归档列表显示专属提示，不诱导用户新建题目。
- 搜索卡片只显示题干摘要和分类信息，不因命中答案或解析而在列表中展示答案。
- 默认按最近收录排序；用户可选到期、最常错或匹配度。匹配度仅在有关键词时有效。

## 5. 主要流程

### 搜索与回看

学生进入“错题” → 在搜索框输入历史题目关键词并确认 → 结果显示匹配数量 → 可继续按章节、错因、日期或状态缩小范围 → 点开记录详情回看。

### 归档与恢复

学生在未归档卡片或详情中点“归档” → 确认 → 记录从活动列表移除但保留在“已归档”中 → 学生可搜索/筛选归档记录 → 点“恢复”并确认 → 记录回到未归档列表，学习数据保留。

### 区分回收站

需要临时收起的记录使用“归档”；需要删除的记录移入回收站。两个动作文字、页面和恢复接口均应区分。

## 6. 验收条件

1. 默认列表不显示归档题；已归档列表可以搜索、筛选和分页查看归档题。
2. 从题干、参考答案、原作答、订正、解析、错因、标签、章节或知识点中的有效关键词均能找到所属题目；列表卡片不得因此暴露答案。
3. 章节、错因、标签、日期、状态和到期筛选可组合使用；清空操作恢复默认查询。
4. 有查询条件时没有匹配项，显示无结果提示与清空入口；归档列表为空时不显示“收录第一题”按钮。
5. 列表归档/恢复需确认；完成后数量与列表及时刷新，且不能触发卡片详情导航。
6. 归档和恢复后题干、答案、解析、附件、标签、练习历史及随笔仍完整；恢复状态遵守 4.2。
7. 软删除记录只出现在回收站；归档记录不能被误认为已删除，恢复回收站的 API 不等同于取消归档。
8. 接口按服务端当前用户隔离；不返回其他用户记录。
9. 在约 10,000 条文本记录和约定本地 MySQL 测试环境中，关键词查询 P95 目标不超过 1 秒；如未达到，记录实际值与设备/数据集并优化。

## 7. 数据与实现约束

- 保持 DDD 现有边界：错题列表、检索、归档和恢复归属 `question` 模块。
- 查询在后端执行过滤和分页；客户端不拉取全量后再筛选。
- 使用 MySQL 8 ngram 全文索引加速中文文本字段；短于两个字符的关键词使用兼容查询路径。
- 归档不改变所有者，不清除任何学习数据；归档恢复由独立接口完成。
- 新的全文索引通过可重复执行的 `database/upgrade-question-search-archive.sql` 提供；运行应用前由项目成员执行。`database/schema.sql` 与升级脚本保持一致。
- 任何搜索结果只提供详情入口；答案仍遵守错题详情默认隐藏、学生主动点开才显示的规则。
